# 19 · Design & taste — zasady, które ratują output przed "AI-lookiem"

Wydestylowane z pracy kreatywnej (obrazki, strony, ady). Uniwersalne, bez brandu.

## Obrazki
- **Kontekst, nie próżnia:** produkt/postać w scenierii — światło, głębia, otoczenie.
  Obiekt na białym tle = AI-slop level 1.
- **Referencje > prompt:** realne foto produktu/logo jako reference image; logo klienta
  NIGDY nie jest przerysowywane przez AI.
- Typografia w obrazkach: zawsze QA wizyjne, znaki narodowe (ą ć ę ł ń ó ś ź ż) osobno sprawdzone.
- Batch: pełny zestaw dostarczany razem (hero + warianty w spójnym layout), nie pojedyncze loose pliki.
- Zakaz: 3D floating text, plastikowe gradienty, "AI glow", pięć wariantów spamu.

## UI / strony
- Strona = ekosystem: +podstrony, +responsive (375px!), +meta/OG/favicon, +stan 404.
- Hard rules: zero lorem ipsum, zero placeholderów w deliverable, zero "object on void" hero.
- Kontrast typograficzny: jedna duża decyzja (display font / mocny kolor), reszta dyscypliny.
-Whitespace robi robotę: mniej elementów, większe odstępy, wyraźna hierarchia.
- Test ostateczny: "dałbym ten link komuś bez wstydu?"

## Copy
- Konkret > abstrakcja: liczba, data, nazwa, cena, przykład zamiast kategorii.
- Głos klienta, nie głos korporacji (patrz też mod. 15 anti-slop).

## Proces
1. Brief → intent (cel, odbiorca, done-criteria) — nawet jednouzdowy.
2. Kanon brandu (kolory/fonty/głos) z pliku, nie z głowy — RECALL w Step Beyond.
3. Produkcja → QA gate (vision/E2E/read-back) → approve → delivery.
4. Odrzucone → regeneracja z korektą promptu, nie "może przejdzie".
